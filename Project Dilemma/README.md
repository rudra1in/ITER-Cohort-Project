# Offline Proctoring - Identity Verification

This project is an identity verification system made for an offline proctoring use case.

The main purpose of the project is to check whether the person present in a verification video matches the person shown in the submitted identity document.

The project uses AI agents for document and video analysis, face embeddings for actual face verification, ChromaDB for vector storage, and Streamlit for the frontend.

## How the Project Works

The user provides two inputs:

1. An identity document image
2. A verification video

The overall process is:

```text
ID Image
   |
   v
ID Analysis
   |
   v
ID Face Embedding
   |
   v
ChromaDB
   |
   |
Video ---> Frame Sampling ---> Face Detection
                                  |
                                  v
                           Video Face Embeddings
                                  |
                                  v
                         Face Verification
                                  |
                                  v
                       VERIFIED / NOT VERIFIED
                                  |
                                  v
                              Ledger
```

The complete workflow is managed using LangGraph.

## Main Components

### ID Agent

The ID agent analyzes the uploaded identity document and extracts information such as:

- Document type
- Name
- Date of birth
- ID number
- Other visible information

### Video Agent

The video agent processes the uploaded video and extracts frames that can be used for further analysis.

### Vision Agent

The vision agent analyzes selected video frames and provides information about the person visible in the video.

This part uses a vision-capable model through the Groq API.

### Face Embedding Agent

The actual identity verification is based on face embeddings rather than the description generated by the vision model.

InsightFace is used to detect the face and generate a 512-dimensional face embedding.

The ID image is also checked in different orientations so that rotated ID photos can still be processed correctly.

### Face Storage Agent

The ID face embedding is stored in ChromaDB.

This allows the system to keep the identity embedding in a vector database and retrieve the closest stored identity during verification.

### Face Verification Agent

The ID face embedding is compared with multiple face embeddings extracted from the verification video.

The system calculates the similarity for the video frames and uses the mean similarity for the final decision.

### Ledger Agent

After verification, the result is stored in an append-only JSONL ledger.

The ledger contains information such as:

- Timestamp
- ID image path
- Video path
- Face similarity
- Verification result
- ChromaDB match
- Verification reason

- Python 3.12 or higher

## Setup

Clone the repository:

```bash
git clone https://github.com/aam-ashim-abinash/offline_proctoring.git
cd offline_proctoring
```

Install the project dependencies:

```bash
uv sync
```

Create a `.env` file in the project root:

```env
GROQ_API_KEY=your_groq_api_key
```

Do not commit the `.env` file to GitHub.

## Running the Application

Start the Streamlit application:

```bash
uv run streamlit run app.py
```

Open the local Streamlit URL shown in the terminal.

Then:

1. Upload the identity document.
2. Upload the verification video.
3. Click `Verify Identity`.
4. Wait for the workflow to finish.
5. Check the verification result and similarity score.

A successful verification will look similar to:

```text
Face Similarity: 0.5368
Verification: VERIFIED
```

The exact similarity value can vary depending on the input images and video.

## Testing

Individual components can be tested using the files inside the `tests` directory.

For example:

```bash
uv run python -m tests.test_graph
```

To test the complete workflow:

```bash
uv run python -m tests.test_full_graph
```

## Verification Method

The final identity decision is based on face embeddings generated by InsightFace.

The ID face produces one 512-dimensional embedding, while multiple faces from the verification video are converted into embeddings.

The system compares these embeddings using cosine similarity.

The current prototype uses a similarity threshold of `0.40`.

The threshold is a project-level value and would need proper calibration with a larger genuine/impostor dataset for production use.

## Important Note

This is a student project and is intended as a prototype for demonstrating an agentic identity verification workflow.

The project currently uses a Groq API for the vision/LLM part, while face detection and face embedding generation are performed locally using InsightFace.

Generated videos, frames, ChromaDB data, model files, and API keys should not be pushed to the repository.
